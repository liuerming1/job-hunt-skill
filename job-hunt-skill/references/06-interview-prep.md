# 06 — 面试准备（interview prep）

> Step 6 与单点面试入口共用。**只对用户明确说要面的一家生成，不批量。** 面试包比简历重得多，且有约 2 周时效，提前生成大概率浪费。

## 前置输入

- 选定岗位的 `jd.md` + `eval.md`（差距清单决定专业题侧重）
- `job-hunt/profile/candidate.md`（项目清单是追问链的原材料）
- config.json 的薪资底线（HR 面口径用）

## 中国市场题型，四层

| 层 | 内容 | 要求 |
|---|---|---|
| 自我介绍 | 按岗位定制的 60 秒版本 + 3 分钟版本 | 60 秒版 = 身份锚点 + 一条最硬证据 + 与岗位的连接；3 分钟版加项目展开。两版都不许复读简历 |
| 项目深挖 | 基于 JD 要求和简历项目交叉生成的追问链，每条追问 2-3 层 | 追问链 = 面试官视角的「为什么→怎么做→结果→如果重来」。每层配答题要点（引用 profile 证据），防背稿 |
| 专业题 | 按方向生成。产品岗：需求优先级、数据指标、A/B 设计、竞品分析；其他职能按对应方法论出 | 题目必须来自这家 JD 的具体业务场景，不出通用八股 |
| HR 面 | 离职原因、薪资谈判、职业规划、反问清单 | 离职原因给口径不给谎话；薪资给「期望值 + 底线 + 谈判让步路径」三段口径；反问清单 5 条，按「显专业 > 显诚意」排序 |

## 模拟面试（roleplay 协议，沿用原仓库）

用户说「开始模拟面试」时进入 roleplay：

1. 你扮演该岗位的面试官，按 暖场 → 专业 → 行为 → 压力题 顺序出题
2. 每题用户答完，先给一句简短反馈（好在哪/弱在哪），再出下一题
3. 压力题环节允许追问到用户答不上来为止——这轮的目的是暴露破绽，不是让对方舒服
4. 结束后出一份复盘：卡壳的题、 backtrack test 会不过的回答、建议重练的题目清单

## 产出（`applications/<公司>_<岗位>/interview.md`）

```markdown
# 面试准备包：<公司> · <职位>
## 自我介绍（60秒版 / 3分钟版）
## 项目深挖追问链（每条 2-3 层 + 答题要点）
## 专业题（按 JD 业务场景出，N 题 + 答题框架）
## HR 面（离职原因口径 / 薪资三段口径 / 职业规划 / 反问清单 5 条）
## 已知风险（eval.md 差距清单里最可能被问的 3 条 + 应对口径）
```

## 时效提醒

交付时告诉用户：面试包按生成时点的 JD 生成，隔两周未用建议重新生成（JD 可能已更新，公司状态可能变化）。
