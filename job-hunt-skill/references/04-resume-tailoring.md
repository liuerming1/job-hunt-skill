# 04 — 简历改造（resume tailoring）

> Step 4 与单点修改入口共用。一期只对用户在 Step 3·6 选定的 1 个岗位执行；用户点名其他岗位时按需追加，规则相同。

## 四条规则

1. **关键词对齐**：JD 的硬性要求必须在简历里有可被 ATS 和人眼检索到的对应表述。不是堆词，是把已有经历换成本行业的说法。
2. **重排不重写**：先用已有的最强证据填 JD 最看重的位置，不够才补。
3. **禁造假，走 backtrack test**：每一条改写，问「面试官追问时，用户能不能不打磕巴地解释」。不能，就退回。这是整个框架里最防翻车的一条（详见 `07-writing-style.md`）。
4. **数字化**：每条经历尽量带结果数据。原简历没有的，标出来让用户补，**不许编**。

## 执行顺序

1. 读 `job-hunt/profile/candidate.md`（不是直接读原始简历——档案里有结构化的证据和占位标记）
2. 读选定岗位的 `postings/.../jd.md` + `eval.md`（差距清单就是改造重点清单）
3. **扫 JD 证书/资质要求**（2026-10-28 新增）：凡明确提到证书（教资、导游证、CPA 等任何表述，含「优先」），先弹提示框问用户是否持有，再动笔
4. 动手前先写改造提纲：JD 最看重的 3 条 → 分别用 profile 里哪几条证据去填 → 哪些位置要重排
5. 产出 `resume.md`（遵守 SKILL.md 的 MD 输出契约）+ `changes.md`

## changes.md 格式（必产）

```markdown
# 变更说明：<公司> · <职位>
## 关键词对齐
- 「内容运营」→「用户增长运营」：JD 任职要求第 2 条原文用了「用户增长」，简历原表述检索不到
## 重排
- P3 项目从第 3 位提到工作经历第 1 位：JD 最看重 0-1 经验
## 待用户补
- P2 项目缺结果数据（转化率提升多少），已标 XX，面试前必须补
## 风险
- 「主导」改成了「参与」：简历原表述夸大，backtrack test 不过
```

按「关键词对齐 / 重排 / 待补 / 风险」四类记录。用户后续点名第二个岗位时，已有的对齐结论直接复用，只针对新 JD 重排，不从零开始。

## MD 输出契约

见 SKILL.md 末尾的契约表，核心：姓名 `#` 唯一、模块 `##` 固定五个、条目 `### 公司 · 职位 · 时间`、要点只用 `-`、禁止表格、日期 `YYYY.MM`。骨架见 `assets/resume.template.md`。

## 长度与克制

- 工作 ≤10 年：一页。>10 年：两页封顶
- 每段经历 3-6 条要点。写不下就删最弱的，不是压缩句子
- 契约禁止表格和深层嵌套是故意的：逼着内容压到最硬的部分

## 底线自查（交付前过一遍）

- [ ] 每条改动都能在 candidate.md 里找到出处，零虚构
- [ ] 所有 XX 占位都在 changes.md「待用户补」里列了
- [ ] 全文没有 `07-writing-style.md` 黑名单里的套话
- [ ] 每条经历能通过 backtrack test
