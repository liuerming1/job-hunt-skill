# 05 — 打招呼语（opening message）

> Step 5。BOSS 上投递的第一动作不是投简历，是发消息。HR 在消息列表里看到的第一句话决定他点不点开你的简历。**这一步和改简历同等重要，不是附属品。** 中国没有 cover letter，一段 100 字的消息取代了它的全部功能。

## 范围

与简历完全同步：用户选定了哪个岗位，就只对这一个岗位生成一段打招呼语，与 `resume.md` 一一配对存在同一个目录（`applications/<公司>_<岗位>/opening.md`）。**每岗位一条，禁止复用**——复用的开头一眼就是群发，直接进 HR 的心理淘汰堆。

## 四段结构

| 部分 | 要求 | 字数 |
|---|---|---|
| 开场 | 直接给身份锚点：几年 + 什么方向 + 一个最硬的标签。**禁止**「您好，我对贵司XX岗位很感兴趣」这类模板开头 | 15-25 字 |
| 核心匹配 | 挑 JD 里权重最高的 1 条要求，用简历里最硬的证据对上，必须带数字 | 30-50 字 |
| 附加价值 | 一条 JD 提到但大多数候选人不具备的东西（跨领域经验、独立项目、行业背景） | 20-35 字 |
| 收尾 | 一句轻量邀约，不卑微不油腻 | 10-15 字 |

**总长 80-120 字。** 超过 150 字 HR 不读；低于 60 字显得敷衍。

## 硬性禁止清单

- 「您好」「打扰了」「冒昧打扰」开头的客套
- 「贵公司/贵司」连用超过一次
- 罗列三个以上形容词（踏实、认真、有责任心）
- 「期待您的回复」之外的任何催促
- 任何简历里没有的经历（backtrack test 同样适用：这句消息里的每个字，用户都要能接住 HR 的追问）

## 生成方法

1. 从 `eval.md` 找出技能匹配维度里 JD 权重最高的那条要求
2. 从 `candidate.md` 找最硬的对应证据（优先带数字的）
3. 附加价值从「JD 提到 + 候选人稀缺」的交集中挑，没有真实的交集就写简历里最独特的一段经历，不编
4. 写完读一遍：删掉所有删了不影响信息量的字

## 产出与交付

- 纯文本一段，落 `opening.md`，对话里直接给全文（这一段就该上屏，方便复制）
- **只生成，不自动发送。** 技术上 CDP 能做，但自动发消息 = 骚扰 + 封号，产品上不做。用户复制粘贴到 BOSS

## 自查

- [ ] 80-120 字
- [ ] 核心匹配带数字
- [ ] 每个字都能通过 backtrack test
- [ ] 禁止清单零命中
