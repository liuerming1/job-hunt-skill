# 01 — 候选人档案（candidate profile）

> Step 0 的产出规范。档案是后续所有判断的基准：方向推导靠它找证据，打分靠它对硬门，改简历靠它取材。**任何在这一步被美化的信息，都会在后面被放大成错误决策。**

## 原则

1. **只抽取，不美化。** 简历里没有的写「XX（待补）」，不许推测补齐
2. **保留证据指针。** 每条关键信息标注它来自简历原文哪一段，后面引用时能溯源
3. **数字化优先。** 凡是带结果数据的条目原样保留数字，这些是打分和改简历最硬的素材

## 档案结构（落 `job-hunt/profile/candidate.md`）

骨架见 `assets/profile.template.md`，字段：

| 字段 | 内容 | 用途 |
|---|---|---|
| 工作年限 | 累计年限 + 分段（如 5 年，其中产品 3 年） | 学历门/履历门、经验匹配 |
| 行业轨迹 | 按时间列：公司（规模/行业）· 职位 · 起止 · 一句话职责 | 方向推导、职业契合 |
| 硬技能 | 技术栈 / 方法论 / 工具，中英文写法都保留（「用户增长」=「UG」） | 技能匹配 30% |
| 项目清单 | 每条 = 动作 + 结果数据 + 角色 + 团队规模。没有数据的标 XX | 改简历主素材、backtrack test |
| 学历 | 学校 · 专业 · 学历 · 全日制/非全日制 · 毕业时间 | 学历门的判定依据 |
| 职级线索 | 带过几人、汇报给谁、是否独立负责产品线 | 经验匹配、文化匹配 |
| 职业目标 | 用户口述的三条（config.json 同步存） | 职业契合 30% |
| 能量/消耗任务 | 用户口述：做什么来劲、做什么耗竭 | 职业契合 30% |

## 采集方式

- 简历文件能解析的直接抽（`scripts/resume_parse.py`）
- 解析不了的（图片 PDF、排版错乱）让用户粘贴文本
- 简历里没有但打分必需的字段（职业目标、能量/消耗、薪资底线、工时底线、学历全日制/非全日制核实），全部并入 Step 1·5 的集中询问，**一次性**问完，写进 config.json
- **Step 1·5 是全流程唯一问询点**：之后任何步骤不得再向用户单独提问采集信息
- 用户拒绝回答的项记「用户未提供」，打分时对应维度降权处理并注明，不许编默认值

## 质量自检（写完档案后过一遍）

- [ ] 每个项目条目都有「动作」，有数据的带「结果数据」，没数据的带 XX 占位
- [ ] 学历写明了全日制/非全日制——学历门直接用它判
- [ ] 硬技能至少覆盖简历原文出现的所有技术名词，中英文对照
- [ ] 没有任何一条是简历原文里找不到出处的
